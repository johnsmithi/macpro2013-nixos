# Решение проблем

## Сеть и загрузка пакетов

- **`unable to download` / загрузки висят, хотя ping работает** — по порядку:
  1. Проверьте часы: `date`. У старых Mac после сброса NVRAM дата улетает,
     и все HTTPS-загрузки падают по сертификатам. Лечится `date -u -s "…"`
     или `systemctl restart systemd-timesyncd`. Разница в минуты или
     «таймзонные» 3 часа (установщик показывает UTC) — не проблема.
  2. Проверьте, кто именно недоступен:
     `curl -I https://cache.nixos.org/nix-cache-info` и
     `curl -sIL https://github.com/NixOS/nixpkgs | head -n1`.
  3. `cache.nixos.org` висит (типично для части провайдеров — это CDN
     Fastly): используйте зеркала — команда в [инструкции по
     установке](install.md#запуск-установки). Зеркала — полные копии официального
     кэша, подписи те же. Если недоступен и GitHub — замените в `flake.nix`
     `nixpkgs.url` на
     `"tarball+https://channels.nixos.org/nixos-26.05/nixexprs.tar.xz"`.
  4. Соединения рвутся «через раз» — добавьте
     `--option http-connections 4 --option download-attempts 10`
     (в установленной системе это уже вшито в конфиг).
- **`cannot build … 1 dependency failed` на множестве пакетов разом** —
  ищите первопричину: `grep "builder for" /tmp/install.log` (запускайте
  установку с `2>&1 | tee /tmp/install.log`). Все загрузки исходников в nix
  выполняются через собираемый им же `curl`, поэтому одна упавшая сборка
  в его цепочке валит каскадом всё остальное. Хвост лога конкретной сборки:
  `nix log /nix/store/….drv | tail -30`.
- **Упала сборка `broadcom-sta`** (настоящая ошибка компиляции, а не
  «dependency failed») — новое ядро ещё не пропатчено. Временно поставьте
  `boot.kernelPackages = pkgs.linuxPackages_6_12;`, после выхода патчей
  верните `pkgs.linuxPackages`.

## Загрузка и графика

- **Установщик виснет/чёрный экран при загрузке ISO** — в меню загрузчика
  нажмите `e` и допишите `nomodeset` (только для установщика; установленная
  система использует правильные amdgpu-параметры).
- **Спам `DMAR: DRHD: handling fault status` в dmesg, подвисания** —
  раскомментируйте `intel_iommu=off` в `boot.kernelParams`
  (известная особенность MacPro6,1).
- **Нестабильность GPU** — запасной вариант: `amdgpu.dpm=0` в `kernelParams`.
- **Композитор ощутимо тормозит** — niri мог выбрать «слепую» вторую D300
  (без дисплейных выходов) как основной GPU. Проверьте
  `journalctl --user -u niri | grep -i drm` и раскомментируйте блок `debug`
  в конце `config.kdl`, указав карту с подключёнными разъёмами
  (`ls -l /dev/dri/by-path`).
- **Монитор через цепочку Thunderbolt не определился** — подключите напрямую
  (miniDP-порты работают как обычный DisplayPort); цепочки TB под Linux
  капризны.

## Wi-Fi

- **Не видит сеть / не подключается** — проверьте, что сеть не WPA3-only:
  драйвер `wl` умеет только WPA2.
- **Wi-Fi отвалился после обновления системы** — свежая серия ядра без
  патчей для `wl`. Верните `boot.kernelPackages = pkgs.linuxPackages;`
  (LTS) или временно `pkgs.linuxPackages_6_12`.

## Разное

- **Bluetooth капризничает при сопряжении** — известная особенность; помогает
  повторное сопряжение, прошивка `.hcd` уже установлена
  (`broadcom-bt-firmware`).
- **Сон не работает** — он сознательно отключён: S3 на MacPro6,1 не
  тестирован сообществом. Хотите экспериментировать — уберите блок
  `systemd.targets.*` из `configuration.nix`.
